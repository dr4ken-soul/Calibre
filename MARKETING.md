# Calibre Marketing and Ecosystem Plan

Status: optional
Submission requirement: no

## 1. Important distinction

The DreamDEX Event Contracts Hackathon submission requirements shown in the supplied materials are:

- working testnet prototype
- GitHub repository
- two to three minute demo video

A post on X is not listed as a required submission item. The marketing plan exists to improve discovery, community feedback, and ecosystem visibility. It must not delay the working prototype.

## 2. Positioning

Short description:

Calibre audits DreamDEX Event Contracts before a trader acts. It compares market probability with an independent estimate, checks liquidity and lifecycle risk, and records what happened after settlement.

One-line version:

Calibre is the audit layer for DreamDEX Event Contracts.

Problem statement:

A directional market price is not enough to justify a trade. Calibre makes probability, execution risk, and settlement inspectable.

## 3. Audience

- DreamDEX Event Contract traders
- Somnia ecosystem builders
- crypto strategy operators
- prediction-market researchers

Secondary:

- AI agent builders

## 5. Community conduct

- Do not spam repeated posts.
- Do not claim a winning result before judging.
- Do not claim profitable trades.
- Do not post wallet addresses or transaction details that expose private information.
- Credit DreamDEX and Somnia accurately.
- Ask before using sponsor logos or marks.
- Reply with technical details when builders ask how the integration works.

## 6. Release assets

Optional assets:

- a short screen recording of the no-trade guard
- a static audit comparison image
- a settlement timeline image
- a short architecture diagram

Do not create a logo or brand symbol for these assets without approval. Use the Calibre word name and the approved interface system.

## 7. Metrics

Track only honest metrics:

- demo visits
- repository visits
- qualified builder replies
- testnet users
- audits completed
- no-trade decisions
- confirmed testnet transactions
- settlement records

Do not use impressions as evidence of product adoption.
